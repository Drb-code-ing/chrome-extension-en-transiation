# Chrome 英文网页 AI 翻译插件需求文档

## 1. 文档信息

- **产品名称**：Chrome 英文网页 AI 翻译插件
- **文档类型**：产品需求文档
- **文档状态**：需求草案
- **适用平台**：基于 Chrome 浏览器的扩展程序

## 2. 产品概述

本产品面向需要阅读英文网页内容的用户。用户在浏览任意英文网站时，可以通过 Chrome 插件提取当前页面的主要文章内容，将文章整理为 Markdown 格式，并交由 AI 大模型翻译为中文。翻译结果在插件界面中以类似 ChatGPT 的打字机效果逐步展示，帮助用户即时阅读译文。

产品采用 **Chrome Side Panel（侧边栏）** 作为主要承载形态：用户从浏览器工具栏打开扩展后，翻译内容固定显示在当前窗口右侧的侧边栏中，不新开标签页、不遮挡原网页，并可在阅读原文与译文时保持上下文关联。侧边栏应绑定当前活动标签页；用户切换标签页时，界面应明确显示当前页面状态，避免将其他页面的翻译误认为当前页面结果。

产品只保留用户最近一次翻译结果，不提供历史翻译记录管理能力。

## 3. 产品目标

1. 降低用户阅读英文文章的语言门槛。
2. 自动识别并提取页面中的主要文章内容，减少无关导航、广告和页面装饰的干扰。
3. 尽量保留原文的标题、作者、链接、正文结构和图片信息。
4. 通过流式、逐步呈现的方式展示翻译结果，提升阅读过程的即时反馈。
5. 在本地保留最近一次翻译结果，方便用户在插件关闭或页面切换后继续查看。

## 4. 用户与使用场景

### 4.1 目标用户

经常浏览英文新闻、博客、技术文章、产品文档和其他长文本网页的 Chrome 用户。

### 4.2 典型场景

用户打开一个英文文章页面，点击浏览器工具栏中的插件图标并发起翻译。插件识别页面主要文章内容，生成包含文章元信息和图片的 Markdown 原文，调用 AI 大模型进行翻译，并在插件界面中动态显示译文。用户可以阅读当前译文；下次打开插件时，如果尚未发起新的翻译，则可以看到最近一次保存的结果。

## 5. 功能需求

### 5.1 启动翻译

- 用户可以从 Chrome 浏览器中打开插件界面。
- 插件应针对当前活动页面发起翻译。
- 翻译操作应显示明确的处理中状态。
- 翻译开始后，用户应能看到译文逐步生成，而不是只能等待完整结果返回。

### 5.2 页面主要内容提取

- 插件应从当前页面识别并提取主要文章区域。
- 提取内容应尽量排除导航栏、页脚、广告、评论区、推荐内容、弹窗和其他非正文元素。
- 应识别文章标题。
- 在页面能够提供作者信息时，应提取作者名称；无法识别时保留为空或使用未识别状态。
- 应获取当前页面的原始 URL。
- 应保留正文中的段落、标题层级、列表、引用、代码块等可识别结构。
- 对无法识别为文章内容的页面，应向用户提示当前页面不适合进行文章翻译，并允许用户重新尝试。

### 5.3 Markdown 内容整理

提取后的原文应整理为 Markdown 内容，并保留必要的文章结构。

正文中的图片必须转换为 Markdown 图片格式：

```markdown
![alt](src)
```

其中：

- `alt` 使用页面提供的图片替代文本；页面未提供时允许为空。
- `src` 使用图片的可访问来源地址。
- 图片应按其在原文中的位置保留在正文中。

### 5.4 AI 翻译

- 插件应将整理后的文章内容提交给 AI 大模型进行翻译。
- 翻译结果应以中文为主要输出语言。
- 翻译应尽量保持原文的结构、段落顺序、标题层级、列表、引用、代码块和图片位置。
- 图片链接和 Markdown 图片语法应保留，不应将图片内容错误地翻译成普通文本。
- AI 输出过程中，插件应持续接收并展示已经生成的内容。
- 翻译完成后，应显示完成状态。

### 5.5 翻译结果展示

翻译结果必须遵循以下固定格式：

```markdown
# [文章标题]

> **作者**: [作者名]
> **原文链接**: [原始文章URL]

[翻译后的正文]
```

展示要求：

- 标题使用一级 Markdown 标题。
- 作者使用引用块展示。
- 原文链接使用引用块展示，并保持为可访问的原始 URL。
- 正文展示翻译后的文章内容。
- 翻译内容以类似 ChatGPT 的打字机效果动态出现。
- 动态展示过程中，已生成的内容应保持可读，不应因后续内容到达而整体闪烁或跳动。
- 翻译失败时，不应将不完整结果误标记为成功结果。

### 5.6 最近一次结果持久化

- 插件只需在本地保存用户最近一次翻译结果。
- 保存内容至少包括最终展示所需的完整 Markdown 结果，以及与其对应的原文页面 URL。
- 当用户重新打开插件时，应优先展示最近一次已完成的翻译结果。
- 新的翻译完成后，应覆盖旧的最近一次结果。
- 不提供历史记录列表、搜索、分类、删除单条记录或恢复旧记录等功能。
- 正在生成但尚未完成的翻译不应被当作已完成结果覆盖本地保存内容。

## 6. 用户界面与交互要求

### 6.1 Chrome Side Panel 产品形态

- 扩展以 Chrome Side Panel 为主界面，点击工具栏图标时直接打开当前浏览器窗口的侧边栏。
- 侧边栏在用户浏览原网页、滚动页面或切换标签页时保持可用；不以 Popup 承载长文译文，不强制跳转到独立扩展页。
- 翻译入口默认作用于当前窗口的活动标签页，并显示可识别的页面标题或域名，帮助用户确认翻译对象。
- 用户切换活动标签页后，应刷新当前页面可翻译状态；不得在未说明来源的情况下将旧标签页内容当作新标签页内容。
- 对 `chrome://`、Chrome Web Store、扩展页及其他浏览器禁止注入脚本的页面，应禁用翻译入口并说明受浏览器限制。
- 关闭并重新打开侧边栏时，应恢复最近一次已完成结果；正在执行的任务如仍可恢复，应显示真实状态，否则应回到可重试状态。

### 6.2 全高长文布局

- 侧边栏使用浏览器提供的完整可用高度，整体布局由顶部固定操作区和下方独立滚动的正文阅读区组成。
- 顶部操作区至少承载当前页面标识、翻译操作与处理状态，正文增长时不得将关键操作挤出可视区域。
- 正文阅读区适配窄宽度，段落、标题、列表、引用和图片不得产生非必要的横向滚动；图片按容器宽度等比缩放。
- 代码块、超长 URL 等不可自然换行内容允许在其局部横向滚动，不得撑宽整个侧边栏。
- 流式翻译期间，仅当用户停留在内容底部附近时自动跟随新内容；用户主动向上阅读后不得强制拉回底部，并应提供返回最新内容的便捷方式。
- 长文持续追加时，已渲染内容和当前滚动位置应保持稳定，不应反复重排、整页闪烁或导致操作明显卡顿。
- Side Panel 宽度变化后，内容应自适应重排，核心操作、状态和正文不得被裁切。

### 6.3 初始状态

- 未存在最近一次结果时，显示翻译入口和当前页面状态。
- 存在最近一次结果时，显示最近一次翻译内容，并提供针对当前页面重新翻译的入口。

### 6.4 处理中状态

- 显示当前正在提取页面或翻译中的状态。
- 用户能够看到已生成的译文内容逐步增加。
- 在任务完成前，避免提供会造成误解的“已完成”提示。

### 6.5 成功状态

- 显示完整翻译结果。
- 明确保留文章标题、作者、原文链接和正文结构。
- 成功结果写入本地最近一次结果存储。

### 6.6 失败状态

以下情况应向用户提供清晰的失败提示：

- 当前页面无法提取主要文章内容。
- 页面内容为空或不适合翻译。
- AI 翻译服务不可用或返回错误。
- 网络中断、请求超时或用户权限配置不完整。
- 翻译结果无法正常完成。

失败提示应说明用户可以采取的下一步操作，例如重试、检查页面或检查 AI 服务设置。失败过程中不应破坏已有的最近一次成功翻译结果。

## 7. 业务规则与范围限制

- 首期只面向英文网页到中文的翻译场景。
- 翻译对象是当前活动页面的主要文章内容，不承诺翻译整个网页中的所有文字。
- 不要求保存多次翻译记录。
- 不要求用户账号体系、云端同步或跨设备同步。
- 不要求对原文进行编辑、批注或二次排版。
- 不要求提供多语言目标语言切换能力。
- 不要求提供人工修改翻译结果后再保存的能力。
- 不要求批量翻译多个页面。

## 8. 权限与隐私要求

### 8.1 最小权限设计

- 扩展采用 Manifest V3，并仅申请实现 Side Panel、当前页提取与本地保存所必需的权限。
- 使用 `sidePanel` 提供侧边栏；使用 `activeTab` 与 `scripting` 在用户点击翻译后访问当前活动页面，避免默认申请 `<all_urls>` 等持续、全站读取权限。
- 使用 `storage` 保存最近一次已完成译文及用户主动配置的 AI 服务设置；不以 `unlimitedStorage` 规避存储约束。
- AI 服务域名仅通过精确的 `host_permissions` 声明；若允许用户配置不同服务，应在实际需要访问对应域名时申请可选主机权限，并允许用户撤销。
- 不申请与本版本能力无关的权限，包括但不限于浏览历史、书签、下载、剪贴板、Cookie 和后台标签页访问。
- 新增或扩大权限范围必须有对应功能依据，并在发布前重新完成权限与隐私评审。

### 8.2 数据处理与用户告知

- 仅在用户主动发起翻译后读取当前活动页面正文，不在后台持续扫描用户浏览内容或记录浏览历史。
- 在首次发送内容前，应明确告知用户：页面标题、作者、原文 URL、提取后的正文及图片链接将发送至所配置的 AI 服务，并说明服务提供方。
- 发送数据应限于完成翻译所需内容；不得发送 Cookie、表单输入、账号凭据、页面存储数据或明显位于正文之外的个人信息。
- AI 请求使用 HTTPS。API 密钥等敏感配置不得写入日志、译文结果或同步存储；界面中展示时应掩码处理。
- 最近一次翻译结果仅保存在用户本地，不建立历史记录服务，不用于广告、画像、分析或模型训练。
- 不引入与核心功能无关的第三方统计、广告或追踪 SDK；如未来增加遥测，必须单独告知、默认最小化收集并提供关闭方式。
- 用户应能清除本地保存的译文和 AI 服务配置；卸载扩展后不应存在由本产品维护的云端副本。
- 隐私政策及 Chrome Web Store 隐私披露应与实际数据收集、传输、存储和共享行为保持一致。

## 9. 验收标准

### 9.1 页面提取

- 在典型英文新闻、博客或技术文章页面上，可以识别文章标题和主要正文。
- 页面导航、广告、推荐内容和评论等明显非正文内容不会成为主要翻译内容。
- 正文中的图片会转换为 `![alt](src)` 格式，并保留在对应正文位置。
- 原文 URL 能够被正确记录。

### 9.2 翻译与展示

- 用户可以从当前 Chrome 页面发起翻译。
- 翻译结果以中文为主，并在界面中逐步显示。
- 结果最终符合规定的标题、作者、原文链接和翻译正文格式。
- Markdown 标题、列表、引用、代码块和图片等结构在翻译后仍可识别和阅读。
- 翻译完成后，结果不会因为关闭并重新打开侧边栏而丢失。

### 9.3 持久化与失败处理

- 插件重新打开时可以展示最近一次已完成的翻译结果。
- 新翻译成功后会替换旧结果。
- 翻译失败不会覆盖最近一次成功结果。
- 无法提取正文或翻译服务出错时，用户可以看到明确的错误状态。
- 产品不出现历史翻译列表或多条结果管理功能。

### 9.4 Side Panel 与长文布局

- 点击扩展工具栏图标后，在当前窗口打开 Chrome Side Panel；不会打开新标签页，也不以 Popup 承载译文。
- 切换活动标签页后，侧边栏展示新页面的标题或域名及可翻译状态；旧译文若继续显示，必须明确标注其来源，不得误标为当前页面。
- 在浏览器禁止扩展读取的页面上，翻译按钮不可用，并显示权限限制提示。
- 在 Chrome Side Panel 可调整的窄、宽尺寸下，顶部操作区始终可见，正文区域独立纵向滚动，无整页非预期横向滚动或内容裁切。
- 使用包含多级标题、列表、引用、图片、代码块和超长 URL 的长文章验证：图片自适应容器宽度，代码块或超长 URL 仅在局部横向滚动。
- 流式生成时，用户位于底部附近会自动跟随新内容；用户上滚离开底部后位置保持稳定，且可以一键返回最新内容。
- 连续生成不少于 10,000 个英文单词对应的译文时，已生成内容不整页闪烁，滚动与顶部操作保持可用。

### 9.5 权限与隐私

- Manifest 权限清单仅包含实现本版本所需的 `sidePanel`、`activeTab`、`scripting`、`storage` 及精确 AI 服务主机权限，不包含 `<all_urls>` 和无功能依据的敏感权限。
- 未经用户主动点击翻译，扩展不读取或发送当前页面正文；首次外发前可看到数据范围和 AI 服务提供方说明。
- 通过网络请求检查确认，仅向已披露的 AI 服务发送完成翻译所需的标题、作者、URL、正文和图片链接，不发送 Cookie、表单内容或页面凭据。
- API 密钥不会出现在控制台日志、网络请求 URL、译文、本地最近一次结果或同步存储中，配置界面仅掩码展示。
- 用户清除本地数据后，最近一次译文与 AI 服务配置均无法从扩展中恢复。
- Chrome Web Store 隐私披露、隐私政策与实测的数据处理行为一致。

## 10. 非功能要求

- 交互应适配 Chrome 浏览器扩展的常用使用方式。
- 翻译结果在动态生成过程中应保持稳定、连续和可阅读。
- 对较长文章应避免因内容持续增长导致界面不可用。
- 本地保存的最近一次结果应在插件重新打开后可靠读取。
- 页面提取和翻译失败时，插件应保持可恢复状态，用户可以重新发起操作。

## 11. 版本范围

本需求文档仅覆盖首个可用版本的英文网页提取、Markdown 整理、AI 翻译、动态展示和最近一次结果本地持久化能力。多语言翻译、历史记录、账号体系、云端同步、批量处理和复杂的人工编辑能力不在本版本范围内。

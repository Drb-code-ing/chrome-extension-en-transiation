# Chrome 英文网页 AI 翻译插件需求文档

## 1. 文档信息

- **产品名称**：Chrome 英文网页 AI 翻译插件
- **文档类型**：产品需求文档
- **文档状态**：需求草案
- **适用平台**：基于 Chrome 浏览器的扩展程序

## 2. 产品概述

本产品面向需要阅读英文网页内容的用户。用户在浏览任意英文网站时，可以通过 Chrome 插件提取当前页面的主要文章内容，将文章整理为 Markdown 格式，并交由 AI 大模型翻译为中文。翻译结果在插件界面中以类似 ChatGPT 的打字机效果逐步展示，帮助用户即时阅读译文。

产品只保留用户最近一次翻译结果，不提供历史翻译记录管理能力。

## 3. 产品目标

1. 降低用户阅读英文文章的语言门槛。
2. 自动识别并提取页面中的主要文章内容，减少无关导航、广告和页面装饰的干扰。
3. 尽量保留原文的标题、作者、链接、正文结构和图片信息。
4. 通过流式、逐步呈现的方式展示翻译结果，提升阅读过程的即时反馈。
5. 在本地保留最近一次翻译结果，方便用户在插件关闭或页面切换后继续查看。

## 4. 用户与使用场景

### 4.1 目标用户

经常浏览英文新闻、博客、技术文章、产品文档和其他长文本网页的 Chrome 用户。

### 4.2 典型场景

用户打开一个英文文章页面，点击浏览器工具栏中的插件图标并发起翻译。插件识别页面主要文章内容，生成包含文章元信息和图片的 Markdown 原文，调用 AI 大模型进行翻译，并在插件界面中动态显示译文。用户可以阅读当前译文；下次打开插件时，如果尚未发起新的翻译，则可以看到最近一次保存的结果。

## 5. 功能需求

### 5.1 启动翻译

- 用户可以从 Chrome 浏览器中打开插件界面。
- 插件应针对当前活动页面发起翻译。
- 翻译操作应显示明确的处理中状态。
- 翻译开始后，用户应能看到译文逐步生成，而不是只能等待完整结果返回。

### 5.2 页面主要内容提取

- 插件应从当前页面识别并提取主要文章区域。
- 提取内容应尽量排除导航栏、页脚、广告、评论区、推荐内容、弹窗和其他非正文元素。
- 应识别文章标题。
- 在页面能够提供作者信息时，应提取作者名称；无法识别时保留为空或使用未识别状态。
- 应获取当前页面的原始 URL。
- 应保留正文中的段落、标题层级、列表、引用、代码块等可识别结构。
- 对无法识别为文章内容的页面，应向用户提示当前页面不适合进行文章翻译，并允许用户重新尝试。

### 5.3 Markdown 内容整理

提取后的原文应整理为 Markdown 内容，并保留必要的文章结构。

正文中的图片必须转换为 Markdown 图片格式：

```markdown
![alt](src)
```

其中：

- `alt` 使用页面提供的图片替代文本；页面未提供时允许为空。
- `src` 使用图片的可访问来源地址。
- 图片应按其在原文中的位置保留在正文中。

### 5.4 AI 翻译

- 插件应将整理后的文章内容提交给 AI 大模型进行翻译。
- 翻译结果应以中文为主要输出语言。
- 翻译应尽量保持原文的结构、段落顺序、标题层级、列表、引用、代码块和图片位置。
- 图片链接和 Markdown 图片语法应保留，不应将图片内容错误地翻译成普通文本。
- AI 输出过程中，插件应持续接收并展示已经生成的内容。
- 翻译完成后，应显示完成状态。

### 5.5 翻译结果展示

翻译结果必须遵循以下固定格式：

```markdown
# [文章标题]

> **作者**: [作者名]
> **原文链接**: [原始文章URL]

[翻译后的正文]
```

展示要求：

- 标题使用一级 Markdown 标题。
- 作者使用引用块展示。
- 原文链接使用引用块展示，并保持为可访问的原始 URL。
- 正文展示翻译后的文章内容。
- 翻译内容以类似 ChatGPT 的打字机效果动态出现。
- 动态展示过程中，已生成的内容应保持可读，不应因后续内容到达而整体闪烁或跳动。
- 翻译失败时，不应将不完整结果误标记为成功结果。

### 5.6 最近一次结果持久化

- 插件只需在本地保存用户最近一次翻译结果。
- 保存内容至少包括最终展示所需的完整 Markdown 结果，以及与其对应的原文页面 URL。
- 当用户重新打开插件时，应优先展示最近一次已完成的翻译结果。
- 新的翻译完成后，应覆盖旧的最近一次结果。
- 不提供历史记录列表、搜索、分类、删除单条记录或恢复旧记录等功能。
- 正在生成但尚未完成的翻译不应被当作已完成结果覆盖本地保存内容。

## 6. 用户界面与交互要求

### 6.1 初始状态

- 未存在最近一次结果时，显示翻译入口和当前页面状态。
- 存在最近一次结果时，显示最近一次翻译内容，并提供针对当前页面重新翻译的入口。

### 6.2 处理中状态

- 显示当前正在提取页面或翻译中的状态。
- 用户能够看到已生成的译文内容逐步增加。
- 在任务完成前，避免提供会造成误解的“已完成”提示。

### 6.3 成功状态

- 显示完整翻译结果。
- 明确保留文章标题、作者、原文链接和正文结构。
- 成功结果写入本地最近一次结果存储。

### 6.4 失败状态

以下情况应向用户提供清晰的失败提示：

- 当前页面无法提取主要文章内容。
- 页面内容为空或不适合翻译。
- AI 翻译服务不可用或返回错误。
- 网络中断、请求超时或用户权限配置不完整。
- 翻译结果无法正常完成。

失败提示应说明用户可以采取的下一步操作，例如重试、检查页面或检查 AI 服务设置。失败过程中不应破坏已有的最近一次成功翻译结果。

## 7. 业务规则与范围限制

- 首期只面向英文网页到中文的翻译场景。
- 翻译对象是当前活动页面的主要文章内容，不承诺翻译整个网页中的所有文字。
- 不要求保存多次翻译记录。
- 不要求用户账号体系、云端同步或跨设备同步。
- 不要求对原文进行编辑、批注或二次排版。
- 不要求提供多语言目标语言切换能力。
- 不要求提供人工修改翻译结果后再保存的能力。
- 不要求批量翻译多个页面。

## 8. 权限与隐私要求

- 插件应仅申请完成当前页面内容读取、翻译请求和本地结果保存所必需的浏览器权限。
- 页面内容发送给 AI 大模型前，应明确属于翻译流程的一部分。
- 除完成翻译所需的请求外，不应收集与功能无关的页面信息。
- 最近一次翻译结果只保存在用户本地，不建立历史记录服务。
- 用户的 AI 服务配置和翻译内容不应在未明确授权的情况下用于其他用途。

## 9. 验收标准

### 9.1 页面提取

- 在典型英文新闻、博客或技术文章页面上，可以识别文章标题和主要正文。
- 页面导航、广告、推荐内容和评论等明显非正文内容不会成为主要翻译内容。
- 正文中的图片会转换为 `![alt](src)` 格式，并保留在对应正文位置。
- 原文 URL 能够被正确记录。

### 9.2 翻译与展示

- 用户可以从当前 Chrome 页面发起翻译。
- 翻译结果以中文为主，并在界面中逐步显示。
- 结果最终符合规定的标题、作者、原文链接和翻译正文格式。
- Markdown 标题、列表、引用、代码块和图片等结构在翻译后仍可识别和阅读。
- 翻译完成后，结果不会因为关闭并重新打开插件而丢失。

### 9.3 持久化与失败处理

- 插件重新打开时可以展示最近一次已完成的翻译结果。
- 新翻译成功后会替换旧结果。
- 翻译失败不会覆盖最近一次成功结果。
- 无法提取正文或翻译服务出错时，用户可以看到明确的错误状态。
- 产品不出现历史翻译列表或多条结果管理功能。

## 10. 非功能要求

- 交互应适配 Chrome 浏览器扩展的常用使用方式。
- 翻译结果在动态生成过程中应保持稳定、连续和可阅读。
- 对较长文章应避免因内容持续增长导致界面不可用。
- 本地保存的最近一次结果应在插件重新打开后可靠读取。
- 页面提取和翻译失败时，插件应保持可恢复状态，用户可以重新发起操作。

## 11. 版本范围

本需求文档仅覆盖首个可用版本的英文网页提取、Markdown 整理、AI 翻译、动态展示和最近一次结果本地持久化能力。多语言翻译、历史记录、账号体系、云端同步、批量处理和复杂的人工编辑能力不在本版本范围内。

# 页面规划与实现步骤总览

> 依据：`docs/proposal.md`（需求文档）、`docs/design.md`（技术架构设计）。
> 本目录（`docs/layouts`）按"页面"分文件，页面内多个模块的布局在每个页面文件中体现。

## 1. 页面与模块划分

插件界面按功能划分为 **2 个页面**，页面内的多个状态/功能模块在对应页面文件中体现：

| 文件 | 页面 | 页面内模块 | 核心动作 |
|------|------|-----------|----------|
| `主界面-页面.md` | 主界面（Popover） | 顶部栏、初始模块、翻译中模块、成功结果模块、失败模块 | 一键翻译、下载结果 |
| `设置页-页面.md` | 设置页（Options） | 模型配置模块、展示偏好模块、关于模块 | 配置模型、密钥 |

## 2. 设计原则

- **力求简约**：不引入冗余功能，围绕"一键翻译 + 下载结果"两个核心动作。
- 主界面为单列布局，正文结果使用 `md-wx` 组件渲染。
- 每次主界面只展示一个状态模块（初始 / 翻译中 / 成功 / 失败），避免信息堆叠。
- 下载动作仅出现在"成功结果模块"，提供原文 Markdown 与译文 Markdown 两种下载。

## 3. 实现步骤（按依赖顺序）

### 阶段 A：项目骨架与构建
1. 初始化 Vite + TypeScript + React 工程，接入 Manifest V3 扩展脚手架，配置 content / background / panel 多入口。
2. 配置 `manifest.json`（`activeTab`、`scripting`、`storage`、下载权限与翻译服务域名）。
3. 引入并确认 `md-wx` 依赖可用，建立共享层目录（`types` / `messages` / `storage` / `constants`）。

### 阶段 B：内容提取链路
4. 接入 Mozilla Readability，实现正文提取与标题/作者识别。
5. 接入 Turndown + GFM，实现 HTML → Markdown 转换（图片 `![alt](src)`、相对路径转绝对）。
6. 实现懒加载图片处理与"无法提取正文"的兜底判定。
7. 内容脚本暴露"提取文章"消息接口。

### 阶段 C：翻译链路
8. 后台层接入 OpenAI 兼容客户端（默认 Qwen / DashScope 兼容地址）。
9. 组装翻译提示词（保留结构、图片语法、输出模板规约）。
10. 实现流式调用与增量块转发；实现超长文章长度预检与截断。
11. 实现错误分类映射（认证/限流/网络/空响应）。

### 阶段 D：界面与交互（对应布局文件）
12. 按 `主界面-页面.md` 实现顶部栏与四态模块（初始 / 翻译中 / 成功 / 失败）。
13. 实现打字机效果与节流刷新；完成后用 `md-wx` 渲染。
14. 实现下载功能（原文 Markdown / 译文 Markdown）。
15. 按 `设置页-页面.md` 实现模型配置与展示偏好。

### 阶段 E：持久化与收尾
16. 实现 `lastResult` 最近一次结果本地读写（成功后才覆盖）。
17. 实现容错：界面状态机、失败不覆盖旧结果、可重试。
18. 单元/集成/手动测试、权限与隐私检查、文档与提交整理。

## 4. 主界面总状态流转（对应各状态模块）

```text
[初始]  → 用户点击一键翻译 → [翻译中] → (流式完成) → [成功]
                  ↑                          (失败) ↓
                  └──────── [失败] ←────────────────┘
```

## 1. 拆分说明

本插件将按以下任务由 AI 分步骤实现。拆分原则：

- **按优先级分层**：P0 基础 → P1 核心链路 → P2 持久化 → P3 辅助功能 → P4 收尾。
- **每个任务独立可完成**：任务聚焦单一功能点，尽量不跨模块；即便前置任务未合并，也提供独立验证方式（mock / 样例）。
- **每步可见效果**：每个任务完成后都能在浏览器中看到明确效果，便于逐步验收。
- **任务内涉及页面/模块**：每个任务标注其实现所依据的布局文件与模块，新增示意元素时在任务内描述清楚。

|--------|------|------|---------------|----------|

| P0 | T2 | 主界面静态骨架与状态切换 | 主界面 · 四个状态模块 | 四态界面可切换 |
| P1 | T3 | 页面内容提取模块 | 主界面 · 初始模块（新增提取预览） | 真实网页提取出原文 Markdown |
| P1 | T4 | AI 翻译流式链路 | 主界面 · 初始/翻译中模块 | 一键翻译，译文流式出现 |
| P1 | T5 | 打字机效果与 md-wx 渲染 | 主界面 · 翻译中/成功模块 | 译文打字机式渲染展示 |

## 3. 依赖关系

```text
P0  T1 工程脚手架 ───────────► T2 主界面骨架
P1  T3 内容提取 ──► T4 翻译链路 ──► T5 打字机与md-wx渲染
P2                          └─────► T6 最近结果持久化
P3                                  ├──► T7 下载/打开原文
P3   T8 设置页（可与 T4/T5 并行，仅依赖存储封装）
P4  T9 错误处理与收尾（依赖全部）
```

**主链路**：`T1 → T2 → T3 → T4 → T5 → T6 → T7`（串行，每步建立在前面基础设施上）
**并行分支**：`T8`（设置页）不依赖 T3/T5/T6，可在主链路推进中并行实现；`T9` 收尾在全部任务后执行。

## 4. 任务详情

---

### T1 工程脚手架与最小可运行扩展（P0）

**目标**：建立可构建、可加载的最小 Manifest V3 扩展骨架。

**依据**：`design.md` §1（技术栈）、§5.1（目录结构）、§5.4（构建选型）。

**涉及页面/模块**：主界面（Popover）顶部栏雏形——参考 `主界面-页面.md` §3。

**实现内容**：
1. 初始化 Vite + React + TypeScript 工程。
2. 接入 Manifest V3 扩展脚手架（`@crxjs/vite-plugin`，WXT 为备选），配置 popup / content / background / options 多入口。
3. 安装依赖：`react`、`react-dom`、`md-wx`、`@mozilla/readability`、`turndown`、`turndown-plugin-gfm`、`openai`、`@crxjs/vite-plugin`。
4. 按 `design.md` §5.1 建立 `src/{content, background, panel, shared, config}` 目录骨架与占位入口文件。
5. 生成 `manifest.json`：声明权限（`activeTab`、`scripting`、`storage`，翻译服务域名 host 权限），popup / content / background / options 入口，占位图标。
6. popup 最小内容：顶部栏"网页翻译助手" + 空状态占位。

**完成标准**：`npm run build` 无错误；`chrome://extensions` 加载 `dist` 后点击图标弹出占位主界面。

**可见效果**：浏览器工具栏出现扩展图标，点击后弹出占位主界面骨架。

**依赖**：无。

**独立验证**：构建产物可直接加载；无需其他模块。

---

### T2 主界面静态骨架与状态切换（P0）

**目标**：按布局文档实现主界面全部状态模块，用模拟数据驱动切换。

**依据**：`主界面-页面.md` §1、§2（骨架）、§3（顶部栏）、§8（布局规则）。

**涉及页面/模块**：主界面 顶部栏 + 初始/翻译中/成功/失败 四个状态模块（互斥展示）。

**实现内容**：
1. 顶部栏：应用标题 + 设置入口（设置入口暂为占位，T8 接通）。
2. 四个状态模块布局，严格对齐 `主界面-页面.md` 的 ASCII 布局：
   - 初始模块：页面信息框 + "一键翻译当前文章"主按钮。
   - 翻译中模块：状态文案 + 译文预览区（暂为占位）+ 进度指示。
   - 成功结果模块：下载/打开操作条 + 译文渲染区（暂为占位）+ 底部操作条。
   - 失败模块：错误文案区 + 重试按钮。
3. 简易状态机：用临时按钮/模拟数据在四态间切换（本任务不接真实数据，界面可独立演示）。
4. 基础样式（单列布局、可滚动渲染区）。

**完成标准**：四态布局与切换行为符合 `主界面-页面.md`；无控制台错误。

**可见效果**：打开 popup 可通过模拟按钮看到四个状态的完整界面。

**依赖**：T1。

**独立验证**：纯前端模拟数据即可演示，不依赖任何真实链路。

### T3 页面内容提取模块（P1）

**目标**：从当前页面提取文章并转为 Markdown，是本插件关键难点。

**依据**：`design.md` §4.1（方案与流程）、§5.1（`src/content`）、§7（消息协议）。

**涉及页面/模块**：主界面 初始模块（新增次要入口"提取预览"，用于验证与展示提取结果）。新增示意元素描述：初始模块"一键翻译"按钮下方增加一个次要文字入口"预览提取的原文 Markdown"，点击后展示提取结果。

**实现内容**：
1. 内容脚本注入与 DOM 克隆（不污染页面）。
2. Readability 提取标题、作者（byline）、正文 HTML。
3. 元数据补充：`og:title`、`article:author`、JSON-LD、`<article>` 语义元素、`document.title` 兜底。
4. Turndown + GFM 转 Markdown：标题 ATX 风格、列表/引用/代码块/表格保留、图片 `![alt](src)`、相对路径基于 `baseURI` 转绝对。
5. 懒加载图片处理（`loading="lazy"`、`data-src`/`data-original`）。
6. 无法提取时的兜底判定，输出 `EXTRACT_EMPTY` / `EXTRACT_FAILED` 错误码。
7. 暴露"提取文章"消息接口（`shared/messages` 定义类型）。
8. 面板"提取预览"入口展示提取到的原文 Markdown（调试与验收用）。

**完成标准**：在典型英文新闻/博客/技术文章页提取结果含标题、作者、URL、正文结构与 `![alt](src)` 图片；非文章页返回明确错误。

**可见效果**：在真实英文文章页点击后，可看到提取出的原文 Markdown（含图片链接）。

**依赖**：T1（面板承载预览入口）；T2 可选（复用其初始模块）。

**独立验证**：提供测试用文章 HTML 样例，单元测试断言标题/作者/图片/结构；无需真实翻译链路。

### T4 AI 翻译流式链路（P1）

**目标**：后台通过 OpenAI 兼容接口（默认 Qwen / DashScope）发起流式翻译，增量转发给界面。

**依据**：`design.md` §4.2（方案与要点）、§5.1（`src/background`）、§7（消息）、§9.2（错误分类）。

**涉及页面/模块**：主界面 初始模块"一键翻译"触发 + 翻译中模块（本任务先用简单文本追加显示，md-wx 渲染由 T5 完成）。未配置 API Key 时，初始模块临时提供一个最小 API Key 输入框（正式配置界面由 T8 提供）。

**实现内容**：
1. 后台注册"发起翻译"消息，引入任务标识关联流式过程。
2. OpenAI 兼容客户端（`openai` SDK）：`baseURL`/`apiKey`/`model` 从设置存储读取，缺省使用 Qwen 兼容地址与 `qwen-plus`。
3. 翻译提示词常量：保留标题层级/列表/引用/代码块/表格，图片语法原样保留，输出固定格式（标题/作者/原文链接/正文），禁止多余解释。
4. 流式调用并逐块转发增量到面板。
5. 超长文章长度预检与按边界截断。
6. 错误分类映射：`AUTH_FAILED` / `RATE_LIMITED` / `NETWORK_ERROR` / `EMPTY_RESPONSE` / `UNKNOWN`。
7. 翻译中的最小状态反馈（进行中、不显示"已完成"）。

**完成标准**：面板发起翻译后，译文增量实时到达并追加显示；各类错误能正确分类并反馈。

**可见效果**：输入或提取到文章后点击"一键翻译"，看到译文内容流式逐块出现。

**依赖**：T1；T3（提供输入，非硬依赖——提供"粘贴测试文本翻译"的调试入口可独立验证）。

**独立验证**：本地 mock OpenAI 兼容接口（模拟 SSE 流），验证增量顺序、完成与错误事件。

### T5 打字机效果与 md-wx 渲染（P1）

**目标**：将流式译文以 ChatGPT 式打字机效果动态渲染，并用 md-wx 正确展示 Markdown。

**依据**：`design.md` §4.3（md-wx 渲染）、§9.1（状态机）；`主界面-页面.md` 模块3、模块4。

**涉及页面/模块**：主界面 翻译中模块（打字机效果）、成功结果模块（md-wx 渲染区）。

**实现内容**：
1. 引入 `md-wx` 的 `MarkdownRenderer` 组件与样式。
2. 翻译中：把增量累积为"当前完整 Markdown"，按节流节奏（如每 200ms 或按块）刷新渲染，避免长文卡顿。
3. 成功后：完整译文用 md-wx 渲染，固定格式 `# 标题`、`> 作者`、`> 原文链接`、正文。
4. 渲染区可滚动、内容稳定（不闪烁不跳动）。
5. 翻译中/成功状态正确切换；翻译中不显示"已完成"。

**完成标准**：译文以 Markdown 渲染 + 打字机效果稳定展示；较长文章渲染不卡顿。

**可见效果**：翻译过程中内容像 ChatGPT 一样逐字/逐段出现，并正确渲染标题、列表、引用、代码块与图片。

**依赖**：T4（流式数据）、T2（状态布局）。

**独立验证**：用模拟增量数据流驱动打字机与渲染，不依赖真实网络。

---

### T6 最近一次结果持久化（P2）

**目标**：在本地保存并恢复最近一次翻译结果。

**依据**：`design.md` §8（存储设计）；`proposal.md` §5.6、§6.1。

**涉及页面/模块**：主界面 初始模块（存在结果时展示最近结果 + 重新翻译入口）、成功结果模块（成功后写入）。

**实现内容**：
1. `shared/storage` 封装 `chrome.storage.local` 读写 `lastResult`（标题、作者、原文 URL、最终 Markdown、保存时间）。
2. 仅翻译成功完成后写入并覆盖；进行中/失败不写入。
3. 打开 popup 时读取 `lastResult` 并优先展示（对应布局"最近一次结果"）。
4. 无结果时的空状态展示。

**完成标准**：翻译成功后关闭并重开 popup 仍可看到结果；失败不影响旧结果；无历史列表能力。

**可见效果**：关闭再打开插件，上一次翻译结果仍能展示。

**依赖**：T5。

**独立验证**：单元测试模拟 `chrome.storage`，验证写入/覆盖/失败不覆盖。

### T7 下载与打开原文（P3）

**目标**：提供译文/原文下载与打开原文操作。

**依据**：`主界面-页面.md` 模块4（下载译文 / 下载原文 / 打开原文）。

**涉及页面/模块**：主界面 成功结果模块操作条。

**实现内容**：
1. 下载译文为 `.md` 文件（文件名取自文章标题并安全化）。
2. 下载原文 Markdown 为 `.md` 文件。
3. "打开原文"按钮在新标签页打开原文 URL。
4. 按需在 manifest 声明 `downloads` 权限。

**完成标准**：成功模块三个操作均可用，下载文件内容正确。

**可见效果**：点击后下载到对应 `.md` 文件、可打开原文页面。

**依赖**：T5。

**独立验证**：手动点击验证文件内容与命名。

### T8 设置页（P3）

**目标**：提供模型配置、展示偏好与数据管理界面。

**依据**：`设置页-页面.md` 全部三模块；`design.md` §8.4（密钥安全）。

**涉及页面/模块**：设置页 模型配置模块、展示偏好模块、数据与关于模块。

**实现内容**：
1. `options` 页面接入（manifest `options_ui`；主界面顶部栏⚙接通）。
2. 模型配置模块：服务基地址、API Key（显示/隐藏）、模型下拉（qwen-turbo/qwen-plus/qwen-max，默认 qwen-plus）、温度滑杆、测试连接、保存。
3. 展示偏好模块：md-wx 主题、跟随系统主题开关、默认视图模式（主界面读取生效）。
4. 数据与关于模块：清空最近一次结果（带确认）、关于信息。
5. `settings` 存储读写封装（`shared/storage`）。

**完成标准**：配置可保存并在主界面翻译与渲染中生效；密钥仅存本地。

**可见效果**：修改 API Key / 模型后翻译使用新配置；切换主题影响译文样式。

**依赖**：T1（options 骨架）；T4/T5（配置生效验证，可后置）。

**独立验证**：单元测试 `settings` 读写与默认值。

---

### T9 错误处理与收尾（P4）

**目标**：完善全链路错误处理、测试与发布收尾。

**依据**：`design.md` §9、§11、§12；`proposal.md` §6.4、§9（验收标准）。

**涉及页面/模块**：主界面 失败模块 + 全局容错；打包产物。

**实现内容**：
1. 全链路失败展示：失败模块按错误码显示文案（提取失败/认证/限流/网络/空响应）+ 重试。
2. 失败不覆盖 `lastResult` 的回归验证。
3. 补充单元/集成测试：提取样例、翻译 mock、存储封装、提示词组装、长度截断。
4. 手动测试清单（对应 proposal 验收标准 9.1/9.2/9.3）。
5. 打包检查：图标、权限最小化、隐私说明（密钥本地存储、内容仅用于翻译）。
6. README 使用说明：安装方式、加载未打包扩展、配置 API Key、使用流程。

**完成标准**：全流程符合 `proposal.md` 验收标准，失败场景可恢复。

**可见效果**：各失败场景均有清晰提示且可重试；文档可指导使用。

**依赖**：全部任务。

**独立验证**：按验收标准逐项手工走查 + 自动化测试通过。

## 5. 执行约定

- 任务按编号顺序执行；每个任务完成后提交一次（提交信息遵循 `design.md` §6.5 约定）。
- 每个任务的"可见效果"为人工验收点，实现时需确保可被用户直接看到。
- 消息协议、存储结构等共享接口变更需同步更新 `design.md` 与类型定义（`design.md` §6.5）。
- 涉及新页面/模块示意时，先补充到对应布局文件或在任务描述中说明，再实现。
